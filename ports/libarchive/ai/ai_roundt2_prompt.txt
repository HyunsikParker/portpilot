You are porting the open-source project libarchive (v3.8.11) to QNX 8.0. It now builds, but some of its own tests
fail when run on a QNX 8.0 x86_64 target. The project was configured and built on a Windows host with the QNX
toolchain (qcc, GCC 12.2, libc++), so build-time scripts and code generators ran on Windows; the tests run on QNX.

Target: QNX Neutrino 8.0 (POSIX, BSD-derived socket API in libsocket, GCC 12.2 via qcc, C++ library libc++).
Things QNX 8.0 does not have: epoll, inotify, eventfd, signalfd, timerfd, <sys/sysctl.h>, <sys/prctl.h>, <execinfo.h>,
<sys/random.h>/getrandom (use arc4random_buf or /dev/random), sched_getaffinity, Linux /proc layout.
Things QNX keeps in libc: pthread, rt, dl, util functions. The compiler defines __QNX__ and __QNXNTO__.
Directory descriptors: the *at() functions (openat, fstatat, unlinkat, mkdirat, ...) fail with ENOTDIR on QNX 8.0 when
the directory descriptor was opened without O_DIRECTORY, e.g. open(".", O_RDONLY); open directories that are used as
dirfd arguments with O_DIRECTORY. On such an O_DIRECTORY descriptor, fstatvfs() fails with ENOSYS and fpathconf() with
EINVAL; both work on a descriptor opened with O_RDONLY, e.g. openat(dirfd, ".", O_RDONLY).
Networking: QNX 8.0 replaced the io-pkt stack of QNX 7 with io-sock, which is based on FreeBSD. io-pkt interfaces such
as <sys/dcmd_io-net.h>, <net/ifdrvcom.h>, devctl(SIOCGDRVCOM) and nic_stats_t are gone; per-interface counters come
from getifaddrs(): AF_LINK entries carry a struct if_data in ifa_data (ifi_ipackets, ifi_opackets, ifi_ibytes,
ifi_obytes). Code written for QNX 7 must be rewritten against these, not just have its includes guarded.
